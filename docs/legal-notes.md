# 开源到 GitHub 的版权/专利风险说明（非法律意见）

> 2026-11-26 ｜ 针对"参考了华为公开专利 CN116964587A 的参数提取与迁移思路，能否开源"的整理。
> 本文只是工程侧的风险清单，不构成法律意见；商用前请找法务做 FTO（自由实施）检索。

## 1. 先把三类权利分开

| 类型 | 保护什么 | 与本项目的关系 |
|---|---|---|
| **专利** | 技术方案（权利要求） | 参考了 CN116964587A 的"参数提取→迁移"流程，需看权利要求是否覆盖我们的实现 |
| **著作权** | 具体表达（文字、图、代码） | 我们的代码/文档是独立写的；只要不抄专利原文/图表，风险低 |
| **商业秘密/NDA** | PDK 模型、库、仿真数据 | **风险最高**：PDK 与派生数据不能公开 |

## 2. 专利（Patent）

- **公开专利可以读、可以引用**：CN116964587A 是公开文本，阅读、引用专利号、在文档里说明"参考其思路"都不侵权。
- **但"实施权利要求"可能侵权**：如果我们的实现实质落入其权利要求（例如"按 gm/Id 与 self_gain 反解尺寸 + 按失配容忍带校正"等），在中国/美国等地域、在专利有效期内，未经许可的实施（含商业使用）可能构成侵权。
- **开源 ≠ 免责**：把代码放到 GitHub 属于公开传播，若他人商用或你商用，专利风险仍在；中国专利法第 75 条的"科研实验例外"范围较窄，不能当然覆盖商业用途。
- **建议**：开源前做一次简单 claim chart（把独立权利要求逐条与我们的实现比对），确认是否"实质相同"；若接近，考虑设计规避（我们与专利的差异点：LUT 实测表 + self_gain 逐管匹配 + 完整验收链，可作为区分点）。

## 3. 著作权（Copyright）

- **方法/思想不受著作权保护**，受保护的是表达。我们独立写代码、独立画流程图，不抄专利附图和表格文字，基本没有著作权问题。
- 引用专利号、写"参考 CN116964587A"是事实性引用，没问题。
- **不要**：复制专利里的参数表原文、附图、大段文字；不要用华为 Logo/商标；不要暗示"华为官方/合作/背书"。
- 若在 README/论文里引用其参数表数字，注明"数据来源：专利 CN116964587A 表 X"（事实数据引用），并避免整表照搬。

## 4. 商业秘密/NDA（最需要小心）

- **PDK 模型、器件库、规则文件（DRC/LVS）**：受 NDA 约束，**绝对不能上传**。
- **由 PDK 仿真派生的数据**（我们的 LUT CSV、网表里的器件名/模型路径、原始 PSF）：很可能被视为 NDA 覆盖的派生数据，**建议不公开**；至少发布前请确认 PDK 许可条款。
- **VM 路径、license 文件、账号信息**：不要进仓库。

## 5. 给 GitHub 仓库的具体建议

1. **代码与数据分离**：仓库只放 `tools/`、`skill/`、`docs/`、`specs/` 等；`runs/` 只保留 README 与结论，原始数据用 `.gitignore` 排除。
2. **加 `NOTICE.md`**（已添加）：声明独立实现、专利引用、无关联、无 PDK 数据。
3. **选许可证**：代码建议 Apache-2.0 或 MIT（明确专利授权条款的差异：Apache-2.0 含专利授权，对下游更友好）。
4. **README 写清**：研究/教学用途、不保证可用于生产、商用需自行 FTO。
5. **不要**打包 PDK、模型、厂商库、VM 镜像。

## 6. 一句话结论

**代码本身（独立实现）著作权风险低；专利风险取决于是否落入权利要求、以及是否商用；最大的实际风险是 PDK/派生数据的 NDA。** 研究性开源一般可控，商用发布前务必做 FTO 与合规审查。
