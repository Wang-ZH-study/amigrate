## 一、上下文

上游 `E:\IC-design-first` 已冻结一个经过 45 点 PVT 验证的两级 Miller 运放 **OPA_D**（8 MOS + Cc/Rz/Rb），原理图在 Virtuoso 的 `weekfour_last / OPA_D` 库里，源 PDK 为 **smic18ee**（SMIC 180nm）。本项目要回答的是：**这张原理图能不能自动迁到 SMIC 的另一套 PDK，并给出可复现的验收证据。**

用户问的"是不是拿一张 SMIC18ee 原理图，用 smic18mmrf 自动迁成一张新原理图"——**方向正确，但有三处要修正**（r1 起目标 PDK 改为 13mmrf，此处的推理仍然成立）：

1. **目标 PDK 要先确认能不能用**：smic18mmrf 只存在于本机 Windows 的 `D:\OPA11\...\CICC0901544_project` 工程里，**未确认能装进 Virtuoso 虚拟机**；VM 里现成的是 smic18ee 和 PDK_13mmrf（130nm，含完整 Calibre）。r1 据此改用 13mmrf。
2. **"自动"指的是映射表驱动，不是 AI 重画**：工具按 Cell/Property/Symbol 三张表换器件、改参数、按引脚重连，拓扑不变；映射表要人写、要 review。
3. **迁完不等于能用**：原理图迁移不保证性能，必须重定尺寸 + PVT 验收（见下"验收"）。

## 二、决策 1：迁移对象与产物形态

- **源**：Virtuoso OA 库 `weekfour_last` 中的 `OPA_D` schematic（smic18ee，已冻结，尺寸 16 字段见上游交付）。
- **目标**：新建目标库（`port_13mmrf`，见 r1）中的一个新 **schematic + symbol** cellview，源库保持只读。
- **产物三件套**：目标原理图、从目标原理图导出的网表（CDL/Spectre）、验收报告。三者必须能互相对上（网表 diff + 手核 2 个管子的 W/L/nf/单位）。
- **"自动迁移"的边界**：换 master、参数改名/公式换算、CDF 回调、分层遍历、自动重连引脚（SPT 后期版本才有；免费 SKILL 脚本**不重连引脚**，必须人工核）。**不**重画拓扑、**不**做版图、**不**保证指标。

## 三、决策 2：目标 PDK 的优先级

| 优先级 | 目标 | 理由 | 前置条件 |
|---|---|---|---|
| **首选（r1）** | **PDK_13mmrf_1P6M_30k**（SMIC 130nm） | VM 内齐全：216 个 OA cell + Calibre DRC/LVS/xRC，能不阻塞地跑通全流程 | 确认 1.2V core 与 1.8V IO 器件档位齐全；确定供电方案（换 IO 器件或降供电） |
| 备选（r1） | smic18mmrf（SMIC 180nm，同节点） | 同节点同电压（1.8V），尺寸近似 1:1，头寸不用重排——文献里最成熟的横向迁移场景（WCAS 2015） | 先把它的 OA 库 + spectre 模型挂进 Virtuoso VM（当前只在 Windows 工程里） |
| 暂不做 | TSMC 65nm OA、CSMC18、X-FAB XT018 | 65nm 只有 Assura、无 1.2V 核心模型；CSMC 同节点意义小；XT018 跨 foundry 差异太大 | — |

**切换条件（r1）**：若 13mmrf 的 1.2V 核心模型或 Calibre 规则在 VM 内不可用，才回退 smic18mmrf（仍需先解决挂载），并在报告里记录该取舍与"跨节点→同节点"的差异。

## 四、决策 3：技术路线（v0）

**网表重定尺寸为主，原理图迁移作试点，学习型方法不进入主链路。**

1. **映射层**：三张表（cell / property / symbol），格式为可 diff 的文本（YAML/CSV），进 Git。参数规则六类：直接沿用、按比例、多参数计算、固定值、设计变量、决策树（对齐 SPT 论文的规则集）。
2. **原理图级试点**：在 IC618 里用 Cadence 公开 SKILL 脚本 `abConvertComponentParams.il` + `abInvokeCdfCallbacks.il` 跑一次真实迁移（schematic → schematic），验证"映射规则能否描述清楚"。
3. **网表级主线**：自建映射器把源网表映射到目标 PDK，生成目标网表；这条路径不依赖任何商业 license，可复现、可回归。
4. **重定尺寸**：用上游已有的随机搜索/差分进化/贝叶斯优化接目标 PDK，恢复指标到容差内。
5. **SPT/新版 Cadence 迁移**：只作为"若拿到 license 则用的加速器"，不是前置条件。

**为什么不用学习型做主链路**：文献里没有任何一篇做到"端到端迁移 + signoff"；学习型只适合做残差修正或长尾劳动。

## 五、决策 4：验收口径

五层（详见 `specs/`，工单 03 落地）：

1. 拓扑与工作点（逐管 Vgs/Vds/Id/饱和区）
2. 物理/网表级检查（ERC；本轮无版图，DRC/LVS 标 out-of-scope）
3. 电气指标容差表（相对源基线，默认允许劣化 ≤5%）
4. PVT 角集 + 蒙卡/最坏情况距离
5. PEX 后仿（本轮只留接口）

**判定规则**：任一层不通过即"迁移未成功"；out-of-scope 不得混入 pass。

## 六、被否选项

| 选项 | 为什么否 |

| 迁到 X-FAB XT018（±20V BCD） | 跨 foundry + BCD 器件（LDMOS/隔离/耐压间距）文献几乎空白；先把同厂流程跑通 |

## 七、后果与风险

- **正面**：不依赖商业 license 也能推进；三张映射表本身就是可复现资产；验收口径可复用给第二个设计。
- **风险 1（r1 已发生）**：改用 13mmrf 后，180→130 的头寸重排可能把"迁移"变成"再设计"，工作量上升；1.8V 供电方案（换 1.8V IO 器件或降到 1.2V 核心）是设计决策，迁移工具定不了。
- **风险 1'**：若 13mmrf 不可用而回退 smic18mmrf，仍需先解决 VM 挂载，等于回到 r1 之前的状态。
- **风险 2**：SKILL 脚本不重连引脚，符号引脚数变化时会错连 → 必须网表 diff + 手核，不能全自动。
- **风险 3**：上游源网表是 Spectre 格式带测试台、原理图是二进制 `.oa` → 需先抽出纯子电路并确认原理图与网表一致（工单 04）。
- **风险 4**：本机内存紧张（两台 VM），仿真与 git 操作要串行。
