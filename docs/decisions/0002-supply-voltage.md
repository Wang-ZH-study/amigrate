# ADR 0002：目标工艺的供电与器件档位（1.2V core vs 1.8V/IO）

- **状态**：**已采纳方案 B**（2026-11-25 用户决定：保 1.8V，用 3.3V IO 器件 n33/p33 在 1.8V 下工作）
- **关联**：05.2、ADR 0001 r1、`specs/migration-spec.toml`（`vdd_nominal_v=1.2`）、`runs/2026-11-25-lut-build/`
- **背景**：OPA_D 在源工艺 smic18ee 上是 1.8V 设计（`n18e2r/p18e2r` 是 1.8V 器件）。目标工艺 13mmrf 只有两档 MOS：**1.2V core（n12/p12）** 与 **3.3V IO（n33/p33）**——**没有 1.8V 档**。

## 一、为什么现在是 1.2V（不是"设计决定"，是器件档位推导出的默认假设）

| 原因 | 说明 |
|---|---|
| 器件档位 | 13mmrf 的快速器件只有 1.2V core；3.3V IO 厚栅氧、慢、面积大 |
| 性能优先 | 跨节点迁移要补回 1.8V→1.2V 的速度/面积损失，用 core 最直接 |
| 工具链已按此建 | 迁移版 LUT 的 Vgs 扫到 1.32V、Vds 到 0.9V，全部是 core 器件参数；候选尺寸也按 core 解 |
| **05.2 尚未拍板** | 这只是"先按最可能方案推进"的工程假设，不是最终决定 |

## 二、1.8V 在 13mmrf 下的隐患（按严重度）

### 1) 直接用 1.2V core 器件跑 1.8V —— 不可接受

- **耐压**：core 器件 Vgs/Vds 额定 1.2V（abs max 约 1.32–1.4V，具体查 PDK Reference Manual），1.8V 超 30–50% → 栅氧 TDDB、热载流子注入、结击穿风险。
- **模型失效**：BSIM 模型只在标称电压附近标定；1.8V 属外推，Vth/gm/速度饱和数字不可信——**仿出来的"达标"没有物理意义**。
- **表也查不到**：迁移版 LUT 只扫到 Vgs=1.32V，1.8V 工作点落在表外，反解器直接报不可行。
- **PDK 检查会拦**：Calibre/ERC 的电压域规则会报 violation（若做 LVS/ERC 的话）。

### 2) 改用 3.3V IO 器件维持 1.8V —— 安全，但代价大

- 厚栅氧 + 更长最小 L → **gm/Id 与 fT 下降**，同样电流需要更大 W，面积与寄生上升；
- 本征增益（gm/gds）可能变差 → 76–78 dB 开环增益更难达标；
- 输入对与输出级的大电容会拖 GBW/PM；
- **必须重建 n33/p33 的迁移版 LUT 并重解 8 管尺寸**——现在的表全白做（core 表不能用于 IO 器件）。

### 3) 系统/接口层隐患

- 1.8V 摆幅与 1.2V 供电不匹配：输入共模到 1.8V 时，输入对 Vgs/Vgd 可能超 1.2V → 需要电平移位、保护或 IO 输入对；
- 输出电压摆幅受 1.2V 电源限制（约 0.2–1.0V 可用），若系统要求 1.8V 摆幅则不满足。

### 4) 头寸（最容易忽略）

上游 04_可行性测绘已指出：OPA_D 的尾电流源 M5 静态余量只有 **97.5 mV**；供电从 1.8V 降到 1.2V 会把它压到接近 0，**SR+ 直接崩**。所以 1.2V 不是"改个标号"，是**重新分配全部头寸**。

## 三、1.2V 的代价（也要说清）

- 输出摆幅、输入共模范围变窄（约 0.2–1.0V）；
- 若目标系统是 1.8V 接口，需要电平移位或接口重定义；
- 头寸重排后，GBW/PM/SR 需要重新优化（08 的活）。

## 四、三个可选方案（05.2 的决策菜单）

| 方案 | 器件/供电 | 优点 | 代价 | 适用前提 |
|---|---|---|---|---|
| **A 全 core** | n12/p12 @ 1.2V | 速度/面积最优；表现有 LUT 与尺寸 | 接口电压降到 1.2V；头寸重排 | 系统接受 1.2V 域 |
| **B 全 IO** | n33/p33 @ 1.8V（甚至 3.3V） | 保持 1.8V 接口与输入范围；耐压安全 | 慢、面积大、增益难；**需重建 IO 表** | 系统必须 1.8V |
| **C 混合** | 输入对/输出级用 IO，内部用 core | 兼顾接口与性能 | 多电压域、寄生与复杂度上升 | 系统 1.8V 且要性能 |

## 五、行业惯例：模拟迁移中"供电能不能变"

**一句话：供电通常不是迁移的自由变量，而是迁移的硬约束；"变供电"更接近"重新定义产品"，不是"迁移"。**

| 迁移类型 | 供电通常变不变 | 器件选择 | 说明 |
|---|---|---|---|
| 同节点横向（180→180 换厂/换 PDK） | **不变**（1.8V→1.8V） | 用对标同电压器件 | 迁移只解决器件/PDK 映射，系统板子不动 |
| 跨节点纵向（180→130/90） | **IO 电压不变、core 电压随节点降** | IO 器件保接口 + core 器件做内部 | 电平移位/混合电压是标准做法 |
| 独立模拟芯片（运放/ADC 等有引脚的） | **不变** | 按数据手册电压选 IO 档 | 变供电=改数据手册/板级兼容性=新产品 |
| SoC 内部模拟 IP | **跟着 SoC 的 core rail 走** | core + IO 混用 | IP 要适配 SoC 电压域，接口走 IO |

**实践判据**：
1. 先看**接口由谁定义**——板级/系统/数据手册定义了 VDD，迁移就必须保住它（用 IO 器件）；
2. 只有"core 电压"允许随节点变化，且变化后必须重做**电平移位、头寸分配、接口规格**；
3. 文献里所谓 "vertical porting 可利用新工艺降供电省功耗"，前提是**产品允许重新定规格**，不是纯迁移。

**对我们这个 OPA_D 的含义**：
- 若它是"要接 1.8V 系统/要保持原数据手册"的独立运放 → **供电不能变**，必须走 B（n33/p33 IO @1.8V）或 C（混合）；
- 若它只是内部 IP、系统核心电压可以跟着 130nm 走 → 可以降到 1.2V（A 方案），但要接受摆幅/共模缩窄与头寸重排，并明确"这是改规格，不是纯迁移"。
