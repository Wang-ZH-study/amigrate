## A. LUT：一张"器件行为的地图"

### A.0 它和设计用的 gm/Id 表是什么关系

**是同一类东西：都是用仿真扫出来的查找表。** 设计用表（上游 `gmid_table.csv`）是"给定 gm/Id、L，查能给出该工作点的 (W, 偏置)"；迁移用表是"给定源电路实测的 (id, gm) 与目标工艺的 (L, Vds, Vsb)，反查 target 的 (Vgs, W)"。差别只在**列、网格和匹配量**：

| | 设计用 gm/Id 表 | 迁移用表 |
|---|---|---|
| 驱动量 | 指标（CL/GBW/PM/SR/P）→ 选 gm/Id、L | 源电路 DC 仿真出的绝对 (id, gm) |
| 匹配量 | gm/Id（归一化相对量） | 绝对特征值 + 失配容忍带（3σ） |
| 缺的列 | 无噪声/无失配/只留饱和行 | 要补 `inoise`、`avt`、`β`，保留非饱和行 |
| 建表成本 | 一次扫描（每工艺一次） | 一次扫描 × 两个 PDK |

所以"迁移方法"的创新点**不在表**，在**匹配判据（带容忍带的绝对特征值）+ 不可行时的 β 缩放回灌**。表只是离线知识，线上一次 DC 仿真 + 查表就能用。

### A.1 它是什么

单个器件（固定 W = 10 µm）在不同 (器件类型, L, Vds, Vsb, Vgs) 下的一组**实测扫描结果**，每行就是一次 DC/噪声仿真：

| 列 | 含义 |
|---|---|
| `dev, L, Vds, Vsb, Vgs` | 扫描自变量（W 固定 10 µm 做归一） |
| `id, gm, gds, vth, vdsat, region, vsat_marg` | 一次 DC 仿真的直接输出 |
| `gmoverid, self_gain` | 派生量：gm/Id、gm/gds |
| `id_W_uAum` | 单位宽度电流密度（反解 W 的关键） |
| `Cgg_per_W, Cgd_per_W, Cdb_per_W` | 单位宽度电容（估寄生/带宽） |
| `inoise_1hz, inoise_10k`（迁移版新增） | 输入参考噪声（闪烁/热噪声） |
| `avt`（迁移版新增） | Pelgrom 失配系数，用来算容忍带 |

数据来源是 **Spectre 实扫**，不是拟合公式。上游设计用的是同一个思路（`gmid_table.csv`，15,166 行 × 20 列），迁移版要补噪声/失配/β 列并保留非饱和行（工单 05.1）。

### A.2 反解器依据什么确定 W/L

**依据两条互相独立的等式，而不是"猜一个尺寸再仿真"：**

1. **工作点匹配（定 Vgs 与 L）**：要求目标器件与源器件的**归一化跨导效率相同**
   ```
   gm_t / id_t  =  gm(L, Vgs, Vds, Vsb) / id(L, Vgs, Vds, Vsb)
   ```
   在 LUT 里按 `gmoverid` 网格 + 线性插值，解出 `Vgs*`。这是"物理匹配"——gm/Id 是工艺指纹，与 W 无关。
2. **电流匹配（定 W）**：归一化电流密度与 W 成反比
   ```
   id_t / W  =  (id / W)|(L, Vgs*, Vds, Vsb)   →   W = id_t / (id/W)
   ```
   `id/W` 由表直接查（`id_W_uAum`）。

所以反解器的输出是一组 **候选 (L, W)**，不是唯一解：不同 L 都能满足同样的 gm/Id，W 随之变化；用残差 + 硬约束挑。

**算法五步**（`tools/solve_lw.py`）：
1. 目标 `gm/Id = gm_t / id_t`；
2. 对每个候选 L 的切片，按 gm/Id 插值解 `Vgs*`；
3. `W = id_t / (id/W)|Vgs*`；
4. 回代校验：用 (L, W, Vgs\*) 重查表得 gm′、id′，算相对残差；
5. **单管解只是候选**：同一支路多管电流由 KCL 耦合，必须喂给电路级 DC 迭代（或优化器）联立，不能逐管各自采纳。

**容忍带（专利的做法）**：目标不必等于源值，只要求落在带内
```
gm_tgt ∈ [gm_org, gm_org + n·σ] ，σ(ΔVt) = Avt / √(W·L)，n = 3（3σ）
```
带内算可行；带外就按 β0/β1 缩放约束再来一轮（工单 09 的回归规则可直接借）。

**不可行时的判定（F0–F4）**：器件不存在（F0）→ 换档位/拓扑；gm/Id 不在该 L 切片可达范围（F1）→ 改 L 或放宽带；W 摊不进指宽窗口（F2）→ 拆并联；电压余量不足（F3）→ 改偏置；表分辨率不够（F4）→ 加密扫描或转 DC 迭代。

### A.3 凭什么信它

三级验证，缺一级都不算数：
1. `--selftest`：用解析表（`id = k·(W/L)·(Vgs−Vth)²`）反解真值，误差应 <1%；
2. **自洽性回归（05.6）**：拿 `sizing_D.csv` 的 8 管（已知 W/L，来自同一张表）反解 W，≥6 管回到 ±5%；
3. **SPICE 抽检**：挑输入对 + 尾电流 2 管，用 Spectre 单管仿真验证"表→反解→SPICE"一致（偏差 <3%）。

第 3 步是关键——没有它，就只是"表自己验证自己"的循环论证。

## B. Cadence SKILL 脚本：怎么换 PDK、输出什么

### B.1 机制（读源码 `abConvertComponentParams.il` v1.7）

```
读 conv.config（S 表达式）
  ↓
对每条规则：dbOpenCellViewByType(toLib, toCell, toView)   ← 打开目标器件符号
  ↓
遍历 cellView 的实例，逐条匹配：
  fromLib / fromCell / fromView —— 锚定正则（"nfet" 即 "^nfet$"）
  propMatch —— 按实例属性再筛（如 subtype="n"）
  matchFunction —— 自定义断言
  ↓
命中后：
  1. 逐参数 dbGet 旧值 → 可选 fixIt(inst, 参数名, 旧值) 做换算 → dbDeletePropByName 删旧属性
  2. dbSetq inst master master        ← 换 master（这是"换 PDK 器件"的关键一行）
  3. dbSet inst 新参数名 新值         ← 写目标参数（w/l/nf/…）
  4. addProps + abInvokeInstCdfCallbacks（重算 CDF 派生参数）
  ↓
全部处理完：schCheck(cellView) + dbSave(cellView)，返回是否有改动
```

批量入口：`...ForLib`（整库所有同 view 的 cell）、`...Hier`（递归遍历层次：`dbGetAnyInstSwitchMaster` 进入子 cellView，跳过 pcell / superMaster / 已访问 / stopList）。

**它没有"转换算法"**：转换规则全部来自 `conv.config`。脚本是执行器，**PDK 差异是数据（配置）**。这就是为什么"能映射新 PDK"= "能写出新 PDK 的配置"，而不是"改脚本代码"。

### B.2 输出是什么

| 项目 | 说明 |
|---|---|
| **产物** | 被修改并 `dbSave` 的 **Virtuoso OA cellView（schematic）**，不是网表、不是报表 |
| **在哪** | 在你打开/指定的那个 cellView 上**原地修改**；跨 PDK 时要先把源库 `dbCopyCellView` 复制到目标库，再在副本上跑 |
| **实例变化** | 每个命中实例的 master 变成目标库器件，参数名/值按规则重写 |
| **不改的** | 引脚连接（`instTerm` 完全不动：引脚本数是名字匹配，名字/数量一变就断）、符号朝向、拓扑 |
| **日志** | 只有 CIW 里的 `printf`（如 "Converting lib/cell/view"）与 `schCheck` 的检查结果；没有结构化报告 |
| **后续** | 网表要由 Virtuoso/ADE 从转换后的 schematic 导出（`simulator`/netlist），不是脚本产出 |

**因此 SKILL 路径的产物边界**：目标库 schematic 骨架 + 导出网表，能挂目标模型跑 `.op/DC/AC`；尺寸仍是源工艺 1:1 搬来的值，**能仿，数先别信**（尺寸由 A 的反解器 + 工单 08 重定）。

### B.3 为什么"PDK 换了、尺寸不换"不是 bug

因为**定尺寸是电学问题，不是数据库问题**：

| 层 | 换什么 | 谁负责 | 需要仿真吗 |
|---|---|---|---|
| 1 | 器件对象（实例的 master 指针） | SKILL：`dbSetq inst master` | 不需要 |
| 2 | 参数名与单位（w/l/nf/m、um→m） | SKILL：`conv.config` 规则 | 不需要 |
| 3 | **尺寸数值（电学最优）** | LUT 反解 + DC 迭代 + 优化器 | **必须** |
| 4 | 版图 / 寄生 | 本轮不做 | 需要 |

脚本里没有仿真器、没有器件模型、没有目标函数——它不可能"算出"新尺寸；硬要它算，就是在脚本里重写一个优化器，那已经是 WiCkeD / Cadence 迁移工具里"重定尺寸"那一半的事了。

**但"只换器件"不是没作用**，它买到三样东西：
1. **一张能在新 PDK 里打开、编辑、仿真的原理图**（拓扑、连接、层次、实例名都在），而不是一张截图或两天的重画；
2. **可执行的映射知识**：器件对应、参数换算、CDF 规则变成可 diff、可 review、可复用的配置文件；
3. **后续数值迁移的容器**：没有这张结构正确的图/网表，反解器和优化器没有东西可跑。

**同时也要承认它的局限**：迁移的最终目的是"在新工艺里能造、性能达标"，SKILL 只走完前半程。
- **同节点横向迁移**（如 180→180 换厂）：器件特性接近，尺寸几乎可以 1:1 沿用 → SKILL + 少量微调基本够；
- **跨节点迁移**（本轮 180→130）：核心器件电压/迁移率/寄生都变，尺寸必须重定 → SKILL 只是起点，05/08/09 才是主体。

一句话：**SPT/Cadence 卖的是"搬结构的苦力活"，不是"定尺寸的设计活"；评估它的价值要按"人工重画/改参数的时间与错误率"算，而不是按"性能是否达标"算。**

## C. 两条路径怎么接

```
源 schematic ──SKILL 换器件/参数──> 目标 schematic（结构对、尺寸旧）
                                        │ 导出网表
                                        ▼
源电路 DC 仿真（取每管 gm_t, id_t） ──反解器查目标 LUT──> 候选 (L, W)
                                        │
                                        ▼
                              DC 迭代 / 优化器收敛 ──> 重定尺寸后的网表 ──> 五层验收
```

SKILL 负责"形状"，LUT + 反解器负责"数值"；两者不重叠，也不能互相替代。
## 术语：gm/Id、self_gain、残差（2026-11-25 补）

| 术语 | 定义 | 单位 | 谁的量 |
|---|---|---|---|
| **gm/Id** | 跨导效率 gm/Id，衡量"每单位电流能换多少 gm" | 1/V | 单管（工作点） |
| **self_gain（本征增益）** | gm/gds，单管作为共源级、理想电流源负载时能给出的最大电压增益 | V/V（也常用 dB：20log10） | 单管（工作点），**不是运放增益** |
| **Aint_dB** | 上游 sizing 表里的本征增益 dB 值 = 20·log10(gm/gds) | dB | 单管（源设计） |
| **残差 residual** | |ln(self_gain_解出 / self_gain_目标)|，回代校验偏差 | 无量纲 | 单管候选解 |

**为什么反解器要匹配 self_gain**：迁移时如果只匹配 gm/Id 和 Id，解出的 L 可能与源设计不同，导致本征增益漂移。把 self_gain 当约束，能保住"这个管子放大能力不变"，从而让整条支路/整级的增益不漂。

**重要区分**：验收指标里的"增益"是**运放的开环增益 Av（dB）**；self_gain 只是**单管代理量**。运放总增益由拓扑与负载决定（近似为各级 gm·(ro||Rload) 的乘积），单管 self_gain 匹配是必要条件，不是充分条件——最终必须用电路级 AC 仿真验证。

**实例（1.8V n33/p33）**：p33 解出 193.7 V/V（45.7 dB）对目标 185.5（45.4 dB），残差 0.043（好）；n33 解出 56.3 V/V（35.0 dB）对目标 123.2（41.8 dB），差 6.8 dB/2.2×，残差 0.783（差）。
